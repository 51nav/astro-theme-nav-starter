# 代码质量修复计划（需求 / 设计 / 任务列表）

## 1. 需求说明

### 背景
当前项目可正常构建，但存在以下工程问题：
- 路由 slug 生成逻辑分散，存在重复和冲突风险。
- Giscus 评论集成配置来源分散，组件可配置性与实际行为不一致。
- 代码中存在未使用函数、重复实现和无效脚本逻辑，维护成本较高。
- 首页锚点存在重复 id 风险，影响页面内导航稳定性。

### 目标
1. 统一 slug 与 favicon 生成逻辑，减少重复代码和行为漂移。
2. 收敛评论区脚本配置，保证组件参数与运行行为一致。
3. 修复重复 id、未使用代码、无效脚本，提高可维护性。
4. 保持现有功能可用并通过构建与静态检查。

### 非目标
- 不改动数据源结构（`config.json` 不新增字段）。
- 不引入新的 UI 框架或状态管理库。

---

## 2. 设计方案

### 2.1 路由与工具层设计
- 新增 `src/utils/slug.ts`：提供统一 `slugify()`。
- 新增 `src/utils/favicon.ts`：提供 `getDomain()`、`getFaviconUrl()`。
- 页面与组件统一调用工具函数，禁止再次手写字符串处理。
- 在 `getStaticPaths` 内做 slug 去重校验，构建期失败优先暴露数据问题。

### 2.2 评论系统设计
- `Giscus` 组件改为“参数完全驱动脚本 data-* 配置”。
- 提交页复用 `Giscus` 组件，不再重复硬编码脚本。

### 2.3 结构与脚本整理
- 首页移除多余锚点容器，避免重复 id。
- 清理未使用 import、未使用函数、无效脚本。
- 简化卡片组件，去除无效 canvas logo 脚本。

### 2.4 验证策略
- 运行 `npm run build` 验证产物构建。
- 运行 `npm run astro -- check` 验证类型与 Astro 诊断。
